# Data Layer

HTTP-сервис поиска мест, отелей, транспорта, состава поездки и ревалидации. Сервис принимает нормализованные параметры от worker; свободный текст пользователя обрабатывает агент.

## Фактическая реализация

- `synthetic`: детерминированные фикстуры отелей/транспорта/трансферов.
- `sandbox`/`live`: read-only LiteAPI `/v3.0/hotels/rates` с `X-API-Key`; при отсутствии ключа — `unsupported`. Отсутствует скрытый fallback на фикстуры.
- В `sandbox`/`live`/`live_transport` дорога берётся из Яндекс Расписаний через `Authorization` (ключ не попадает в URL). `live_transport` — совместимый alias с обоими API. Без соответствующего ключа источник возвращает `unsupported`; трансферы пока не реализованы.
- Яндекс: прямые рейсы, поезда и автобусы в пределах покрытия источника, до 100 исходных сегментов на сторону. Для новых городов nearest_settlement сопоставляет проверенные координаты с кодом Яндекса: проверяются название и расстояние до 50 км. Адаптер проверяет даты/timezone и объединяет до 20 комплектов туда/обратно. Цены справочные: неизвестная цена и детский тариф — `null`, наличие мест не подтверждено (`availability=schedule`), TTL 10 минут. Багаж и питомцы требуют согласования с перевозчиком.
- Встроенный каталог `places.py` дополнен глобальным поиском через [GeoNames/Open-Meteo](https://open-meteo.com/en/docs/geocoding-api). Динамический ID стабилен (`city:geonames_<id>`); возвращаются проверенные страна, координаты и IANA timezone. Точные имена предпочитаются совпадениям по префиксу; неоднозначные города не сливаются. Неверный timezone не подменяется Москвой. Registry ограничен 2048 записями. Публичный endpoint геокодера предназначен для некоммерческого MVP.
- LiteAPI запрашивает до 50 отелей вместо первых десяти; для динамических городов используются координаты и радиус 20 км. География определяет область поиска, но не подтверждает наличие жилья или транспорта.
- Тариф покрывает все ночи, номера и запрошенных гостей. 1–10 номеров, минимум один взрослый на номер в LiteAPI. Известные обязательные сборы добавляются к сумме; неизвестные не считаются включёнными.
- Sandbox/live предложения получают режим из фактического ответа LiteAPI, а не из имени настройки. Sandbox не является рабочим наличием.
- Повторный booking token не меняет логический ID тарифа; цена и условия входят в content hash. Временный registry ограничен по TTL и размеру; после рестарта неизвестный оффер требует нового поиска.

## HTTP-контракт

Актуальные запросы и поля ответа: [PARSER_CONTRACT.md](../agent_worker/PARSER_CONTRACT.md). Все `/internal/v1/*` требуют `Authorization: Bearer PARSER_SERVICE_TOKEN`. Проверка доступности: `GET /health`.

Поиск отелей принимает `destination_id`, `check_in`, `check_out`, `guests`, `rooms`, `constraints`. `meal_plan`: `none` (alias `room_only`), `breakfast`, `half_board`, `full_board`, `all_inclusive`; пустое/unknown — без фильтра. Фактические неизвестные условия остаются `unknown`. Неподдерживаемый фильтр не игнорируется молча. Синтетика поддерживает только свои условия питания и возвращает `unsupported` для остальных.

`budget` в поиске — контекст полной поездки: не отрезать компонент отдельным бюджетным фильтром. Проверка итоговой сборки выполняется `compose`/агентом. Транспорт для полной поездки возвращается одним предложением `round_trip_all_guests` с обеими сторонами и единой суммой. Два отдельных предложения нельзя складывать без явного объединения в адаптере.

429/503 — временная ошибка, а не пустая выдача. `empty` означает успешный поиск без предложений; `unsupported` — отсутствие поддержки; `partial` — предложения с предупреждениями о неполном покрытии.

## Запуск и проверки

Из корня репозитория: `docker compose up --build -d`. Самостоятельно: `pip install -r data_layer/requirements.txt`, затем `python -m uvicorn data_layer.service.api:app --port 8080`.

Конфигурация: `DATA_MODE`, `PARSER_SERVICE_TOKEN`, `LITEAPI_KEY`, `YANDEX_RASP_API_KEY`, `GUEST_NATIONALITY`, HTTP timeout/retry настройки в `config.py`. Никогда не сохраняйте ключи в исходниках. Реальный агент вызывает data-layer только при `AGENT_MODE=openai`; demo использует встроенный provider.

`python -m pytest data_layer/tests tests -q` проверяет HTTP wire contract, синтетические предложения, TTL/ревалидацию, цены/условия LiteAPI через mock транспорта и совместимость с worker/backend. Opt-in проверка настоящих ключей: `python scripts/check_providers.py --extract`. Она выполняет только поиск, без бронирования/оплаты.

Дополнительные технические сведения и прежние эскизы: `INTEGRATION.md`, `adapters/README.md`; при расхождении форматов приоритет у актуального контракта и исполняемых contract tests.
