## Граница готовности продукта

Проверен и работает MVP подбора и редактирования поездки с правдивыми источниками. У предоставленного LiteAPI ключа ответы помечены **sandbox**. Это не рабочее наличие и не подтверждённая цена для покупки. OpenAI работает с настроенной моделью; API-ключи сохранены локально.

Остаются самостоятельные функции/условия для полноценного коммерческого сервиса:

1. Расширение транспорта за пределы прямых маршрутов между пятью подключёнными городами и реальные трансферы. Яндекс Расписания подключён 27 октября; расписание не подтверждает места и конечные тарифы.
2. Production-доступ LiteAPI и проверки реального наличия/условий перед оформлением. Смена DATA_MODE не превращает sandbox-ключ в рабочий.
3. Бронирование, корзина, оплата, отмена, возвраты — в текущем продукте отсутствуют. Ни одна покупка этим аудитом не совершалась.
4. Коммерческий тариф/свой инстанс глобального геокодера при коммерческом запуске; timezone/гражданство должны соответствовать реальному пользователю. Глобальный поиск GeoNames/Open-Meteo добавлен 28 октября.
5. Публичный deployment: HTTPS, Secure cookies, собственные секреты, rate limiting, backup/restore и мониторинг/DLQ. Локальный Compose не подтверждает SLA или нагрузочную готовность.

Эти пункты нельзя считать исправленными только потому, что локальный сценарий и тесты проходят. Неподключённые функции отражаются пользователю явно; цены, дорога и подтверждения не выдумываются.

## Исправление нерелевантного выбора направлений — 28 октября 2026

В проблемном запросе про тёплое море worker подставил общий список Казань/Петербург/Сочи. В кеше реально находились по 20 предложений дороги для каждого города, но route-only assembly показывал первые три из первого города. Поэтому объяснение ошибочно сообщало об отсутствии дороги в Сочи. Основная причина — выбор и отбор агента; ограниченный встроенный справочник парсера дополнительно мешал поиску других городов.

Убран общий fallback, добавлен структурированный выбор городов по цели и сезону, сохранение цели/происхождения выбора, миграция старых автоматических идей. Полные и частичные карточки сохраняют разные направления. Статусы empty/unsupported/unavailable различаются в search_summary; отсутствие карточки не позволяет делать вывод об отсутствии предложений. При сбое разрешения отправления жильё всё равно ищется.

Глобальный геокодер возвращает проверенные координаты, страну и timezone; LiteAPI ищет по координатам, Яндекс сопоставляет код города с проверкой названия и расстояния. Увеличено число просмотренных отелей с 10 до 50; разные виды транспорта сохраняются среди кандидатов. Реальными запросами подтверждены жильё/дорога в Хургаду и жильё в Токио; сохранённый успешный выбор модели проведён через настоящие API и дал разные тёплые направления с LiteAPI и Яндексом. Это явно обозначенный replay выбора, без подмены инвентаря провайдеров.

Полный новый LLM-прогон ограничен HTTP 429 OpenAI: на момент проверки 0 оставшихся запросов из лимита 50. Ключ не менялся, лимит не обходился; дальнейшие provider-проверки не вызывают OpenAI. scripts/check_destination_search.py --replay использует сохранённый успешный ответ выбора городов, --live выполняет полностью живой сценарий после восстановления квоты.

Дополнительно исправлено сохранение больших результатов: служебный offer_cache ограничен 160 KiB, сохраняет выбранные факты; усечённый кеш не подменяет новый полный поиск. Реальный patch уменьшился с 448337 до 74835 байт и успешно сохранён через backend (раньше получался HTTP 422, лимит 256 KiB). Итоговые регрессионные проверки — 198 Python-тестов; один opt-in тест брокера пропущен. UI-проверка использует отдельный тестовый чат с реальными ответами поставщиков и сохранённым выбором модели, без нового обращения к OpenAI.

При сравнении нескольких городов название чата и заголовки карточек не объявляют первый город выбранным. При неизвестной цене билетов сравнивается только известная стоимость жилья; полная поездка не называется дешевле. Длительность дороги показывается в часах и минутах.
